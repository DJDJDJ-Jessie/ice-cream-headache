# QQ 宠物桌面企鹅复刻产品文档

## 1. 产品目标

本项目目标是复刻原版 QQ 宠物企鹅在 Windows 桌面上的体验。

最终产品应该是一个可直接运行的 Windows `.exe`，在 Windows 10 和 Windows 11 上打开后，企鹅直接出现在用户桌面上，而不是出现在浏览器、模拟 XP 桌面、普通应用窗口或网页容器里。

一句话目标：

> 做一个尽量一比一复刻原版 QQ 宠物企鹅的 Windows 桌面宠物。

## 2. 产品原则

1. 桌面优先  
   企鹅本体必须直接站在 Windows 桌面上，透明背景、无边框、可拖拽、可置顶。

2. 原版优先  
   已确认的原版行为优先于现代化改造。没有确认的原版文案、动作、菜单和数值，不允许当成正式还原加入。

3. 先准确，再丰富  
   动作、菜单、数值、文案没有确认前，不继续堆功能。

4. 少发明  
   不写自创对白，不设计现代化面板，不做营销式界面，不用“看起来像桌宠”的替代方案冒充原版。

5. 离线可运行  
   目标版本不依赖腾讯旧服务器。存档、本地状态和资源都应随 `.exe` 或本地数据存在。

## 3. 用户体验目标

### 3.1 启动体验

目标：

- 双击 `.exe` 后，企鹅直接出现在桌面。
- 不出现 XP 桌面模拟器。
- 不出现浏览器窗口。
- 不出现 Ruffle Logo、加载水印或现代启动页。
- 如果原版存在启动动画或登录流程，需要在确认资料后复刻。

当前限制：

- 现阶段只做本地桌宠，不接入旧 QQ 登录。
- 在没有确认原版启动文案前，不显示任何自创启动气泡。

### 3.2 桌面存在感

目标：

- 企鹅透明贴在桌面上。
- 企鹅可拖动。
- 企鹅不应在任务栏出现普通应用按钮。
- 企鹅可通过托盘图标显示、隐藏、退出。
- 企鹅动作应自然连续，不应露出播放器底层、加载层或白/黑底。

验收：

- 桌面上只能看到企鹅本体和原版应该出现的 UI。
- 切换动作时不能看到 `ruffle`、加载条、播放按钮、白底或黑底。

### 3.3 动作体验

目标动作集合：

- 待机
- 走路
- 拖拽
- 落地
- 喂食
- 喝水
- 清洁
- 逗宠
- 学习
- 打工
- 生病
- 升级
- 死亡或濒危状态
- 心情/状态动作

产品规则：

- 任何动作接入主程序前，必须先在动作查看器中确认含义。
- 不允许仅凭文件名猜测后直接作为正式动作。
- 未确认动作可以进入“待验证”清单，但不能进入默认随机行为。

### 3.4 交互体验

目标：

- 鼠标左键拖动企鹅。
- 鼠标右键打开原版风格菜单。
- 状态入口可查看昵称、等级、饥饿、清洁、心情、健康、元宝等信息。
- 当饥饿、清洁、健康等状态异常时，按原版方式提示用户。

当前约束：

- 原版菜单视觉没有确认前，右键菜单只作为临时开发入口。
- 原版提示文案没有确认前，不显示自创对白。

### 3.5 养成系统

目标还原范围：

- 饥饿值
- 清洁值
- 心情值
- 健康/生病
- 成长值
- 等级
- 元宝
- 食品
- 日用品
- 药品
- 学习
- 打工
- 小游戏
- 宠物社区入口

产品规则：

- 数值公式必须能追溯到原版资料、旧客户端行为或明确标注为“近似模拟”。
- “近似模拟”不能伪装成一比一还原。

### 3.6 可执行文件交付

目标：

- 主要交付物是一个可双击运行的 `.exe`。
- 便携版优先，安装版可选。

当前命令：

```powershell
npm run build:exe
```

当前产物：

```text
dist/QQ Penguin-0.1.0-x64.exe
```

## 4. 非目标

以下内容不是当前目标：

- 复刻完整 Windows XP 桌面。
- 在应用窗口里嵌套 QQ 宠物。
- 先做现代化 UI 再回头还原原版。
- 自创剧情、自创对白、自创数值系统并称作原版。
- 依赖旧腾讯服务器才能启动。
- 接入真实 QQ 账号或真实线上服务。

- 默认只播放已确认动作
- 解决动作切换闪屏

状态：下一阶段主线。

目标：

- 还原右键菜单结构
